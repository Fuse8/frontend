## Верстка

### Знания:

- Уметь верстать семантическую, адаптивную, кроссбраузерную верстку
- Уметь верстать с помощью flex, grid
- Уметь использовать preload, prefetch для важных ресурсов, например, шрифтов, стилей, изображений и др.
- Знать практики по работе с изображениями (responsive images, srcset, picture, object-fit, aspect-ratio)
- Понимать что такое доступность и для чего она нужна
- Понимать блочную модель. Знать отличия block, inline, inline-block
- Понимать позиционирование
- Понимать специфичность CSS селекторов
- Понимать различные единицы измерения: px, em, rem, vh, vw, ch и тд.

### Практики:

1. Используем на проекте сброс стилей или нормализацию. Например, (Normalize.css)

   Подключение отдельным css файлом (можно скопировать в проект)
   https://github.com/necolas/normalize.css/blob/master/normalize.css

    1.1 Учитывать, что могут быть конфликты при подключения сторонних ui библиотек, так как ui библиотеки часто используют свой сброс стилей

2. Не использовать !important. Повышаем специфичность селектора без !important.

   2.1 Применяем !important, только когда нужно перебить !important

   2.2 Когда нужно перебить инлайн стили

   2.3 Когда нужно перебить стили библиотеки (например, antd)

3. Не писать лишние стили и теги

   3.1 Например, для блочных элементов не писать `width: 100%`

   3.2 Наследуемые свойства цветов, шрифтов

   3.3 Лишний `flex`, с `flex-direction: column` без использования `gap` так как блочные элементы и так друг под другом

   ```css
   .card {
   	display: flex;
   	flex-direction: column;
   }

   .title {
   	margin-bottom: 16px;
   }
   ```

   ```html
   <div class="card">
   	<h3 class="title">Title</h3>
   	<p class="description">description</p>
   </div>
   ```

   3.4 Лишний тег `span`

   ```html
   <div>
   	<h1 class="title"><span>Title</span></h1>
   </div>
   ```

4. Стараться следовать дизайну насколько это возможно, без pixel perfect, если это не требуется.

   4.1. Если в дизайне есть система отступов, например, кратность 4px, то везде следовать этому правилу. Если где-то в дизайне 13px, то мы должны делать 12px.

5. Компонент должен быть максимально "сырым". Все внешние отступы (margin) и другие свойства, которые влияют на его расположение относительно других элементов, должны задаваться извне, а не внутри самого компонента.

6. В первую очередь используем подход mobile first. Desktop first стоит использовать, когда нет мобильных дизайнов.

7. Не фиксируем высоту или ширину компонента, если не используем скролл. Вместо этого используем `min-height`, `max-height`

8. Используем `box-sizing: border-box` (часто включен в сброс стилей/нормализацию)

```css
*,
*::before,
*::after {
	box-sizing: border-box;
}
```

9. Используем stylelint на проекте. Подключаем автоматическую сортировку правил.

10. Не использовать амперсанды повсеместно `&` в scss/sass, так как усложняет поиск селектора.
    Допустимо использовать в псевдоэлементах, псевдоклассах, модификаторов.

Плохо:

```css
.card {
	font-size: 16px;

	&__title {
		&-large {
			font-size: 40px;

			&:hover {
				color: red;
			}
		}
	}
}
```

Хорошо:

```css
.card {
	font-size: 16px;

	&.md {
		font-size: 18px;
	}

	&.lg {
		font-size: 20px;
	}
}

.card__title--large {
	font-size: 40px;

	&:hover {
		color: red;
	}
}
```

Допустимо:

```css
.card {
	font-size: 16px;
}

.card__title {
	&--large {
		font-size: 40px;

		&:hover {
			color: red;
		}
	}
}
```

11. Изображения

    11.1 Указывать размеры `width`, `height`

    11.2 Указывать alt

    11.3 Оптимизировать изображения с помощью lossless оптимизации

    11.4 В приоритете использовать avif, чем webp формат

    11.5 Предусматривать изображения 2x для ретины дисплеев

    11.6 Добавлять `loading="lazy"` для изображений, которые не во вьюпорте. Для изображений, которые должны загрузиться как можно раньше используем `fetchpriority`

12. Семантика важнее визуала — стили опираются на семантическую разметку.

    12.1 Если это переход куда-то, то `<a>`, если какое-то действие, то `<button>`

    12.2 Соблюдать иерархию заголовков от h1 до h6

    12.3 Уметь использовать семантические теги: `<main>`, `<aside>`, `<figure>` и др

    12.4 Для списков использовать `ul > -> li`, а не `div > div`

13. Делать hover, active состояния, если дизайнер их не сделал, то уточнить у дизайнера, если дизайнера нет, можно самим.

    Для стилей фокуса можно использовать :focus-visible.

14. Для основных заголовков использовать `text-wrap: balance`. Для подзаголовков или текста, у которых много строк можно использовать `text-wrap: pretty`, но без фанатизма, так как влияет на перфоманс.

15. Используем переменные для цветов, шрифтов, z-index и других переиспользуемых значений.

    Особое внимание стоит уделить z-index:

    ```css
    $z-index-header: 5;
    $z-index-popover: 10;
    $z-index-modal: 100;
    $z-index-communication-center: 200;
    $z-index-notification: 1000;
    ```

16. Предусматривать `currentColor` для одноцветных svg иконок

17. Один файл компонент — один файл стилей

```js
// product-card.tsx
// product-card.module.scss

// header.tsx
// header.module.css
```

18. Шрифты

    18.1 Для шрифта используем `font-display: swap;` Чтобы избежать FOIT.

    18.2 Если есть проблема отображения шрифта в safari применить -webkit-font-smoothing

19. Нужно тестировать верстку на переполнение контента, добавлять, уменьшать контент и чтобы она была не ломалась.

20. Верстка должна быть валидной. Можно проверить с помощью [w3c validator](https://validator.w3.org)

21. Использовать `transition` только точечно для свойств, которые меняются вместо `transition: all`

    21.1 Использовать `will-change`, если тормозит анимация

    22.2 Использовать `prefers-reduced-motion`, если нужно отключить анимацию

22. Если интерактивный элемент маленького размера, то увеличить его с помощью псевдоэлемента

23. Стилизовать только по классам. Исключения, когда нужно написать стили для вывода rich text, где нужно использовать селекторы по тегам

### Доступность

Для тестирования доступности можно использовать [browser extension](https://wave.webaim.org/extension/)

1. Интерактивные элементы доступны через tab
2. У элементов без текста добавлен aria-label

```html
<button aria-label="увеличить количество">+</button>
<button class="menu" aria-label="меню"></button>
```

3. У изображений добавлен alt

4. Порядок фокуса: логический порядок перехода по элементам с помощью Tab соответствует визуальному порядку

5. Видимый фокус: У всех элементов есть четко видимый стиль состояния :focus (не удалять outline без альтернативы)

6. Контраст цвета. Опираемся на здравый смысл, если на фоне текст плохо читается, то подсвечиваем дизайнеру. Для проектов с определенным уровнем доступности соблюдаем цветовой контраст, например, WCAG AA (минимум 4.5:1), можно проверить в lighthouse

7. Скрываем заголовки или важный контент, который должен быть доступен для SEO и доступности с помощью техники `visually-hidden`, а не `display: none`

```css
.visually-hidden {
	position: absolute;
	width: 1px;
	height: 1px;
	margin: -1px;
	clip: rect(0, 0, 0, 0);
	clip-path: inset(50%);
	overflow: hidden;
	white-space: nowrap;
	border: 0;
	padding: 0;
}
```
8. Учитывать доступность при написании кастомных компонентов, например, checkbox, radio button, select и др.
